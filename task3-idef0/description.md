# Описание итоговой IDEF0-модели

Моделируемая функция: **«Обработать заказ клиента на маркетплейсе Ozon»**. Контекстная диаграмма `a0_context.drawio` показывает весь процесс как один функциональный блок A-0. Декомпозиция `a0_decomposition.drawio` раскрывает эту функцию на пять подфункций: принять заказ, проверить оплату и наличие, подготовить отправление, организовать доставку и завершить заказ.

## Контекстные дуги A-0

| Тип дуги | Название дуги | Пояснение |
|---|---|---|
| Input | Данные заказа | Состав корзины, количество товаров, выбранный способ доставки и данные клиента. |
| Input | Сведения о товарах | Информация о наличии, цене и характеристиках товаров. |
| Control | Правила платформы | Внутренние правила обработки заказов и взаимодействия с продавцами. |
| Control | Регламент обработки | Порядок проверки оплаты, наличия, сборки и передачи заказа. |
| Control | Условия доставки | Ограничения по срокам, адресам, пунктам выдачи и способам доставки. |
| Output | Обработанный заказ | Заказ, который прошёл основные проверки и получил итоговый результат. |
| Output | Финальный статус заказа | Доставлен, отменён, не оплачен или передан в поддержку. |
| Output | Уведомление клиенту | Сообщение клиенту о состоянии заказа или проблеме. |
| Mechanism | Система Ozon | Цифровая платформа, которая связывает участников и хранит статусы. |
| Mechanism | Склад / продавец | Исполнитель подготовки товара к отправке. |
| Mechanism | Логистика | Ресурс для перемещения заказа до клиента или пункта выдачи. |
| Mechanism | Платёжный сервис | Инструмент проверки и подтверждения оплаты. |

## Логика декомпозиции A0

Декомпозиция построена так, чтобы показать основные функции процесса без перегрузки деталями. Сначала блок A1 **«Принять заказ»** получает данные от клиента и фиксирует заказ в системе. Затем A2 **«Проверить оплату и наличие»** определяет, можно ли продолжать обработку. Если заказ подтверждён, A3 **«Подготовить отправление»** превращает заказ в физически готовую посылку. После этого A4 **«Организовать доставку»** передаёт отправление в логистический маршрут. Последний блок A5 **«Завершить заказ»** фиксирует итоговый статус и формирует уведомление клиенту.

Такой набор блоков соответствует правилу IDEF0: на одной диаграмме не больше шести функций, каждая функция названа глагольной группой, а дуги описывают данные, правила, результаты и ресурсы. Контекстные дуги с уровня A-0 отражены на уровне A0: данные заказа поступают в первый блок, правила и регламенты управляют всеми функциями, а система Ozon, склад, логистика и платёжный сервис выступают механизмами выполнения.
