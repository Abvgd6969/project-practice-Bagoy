# Описание итоговой BPMN-диаграммы

Смоделирован процесс **«Обработка заказа клиента на маркетплейсе Ozon»**. В основной диаграмме используются четыре дорожки: «Клиент», «Система Ozon», «Продавец / склад» и «Логистика». Такое разделение выбрано потому, что действия выполняются разными участниками: клиент создаёт заказ, система проверяет оплату и наличие товара, склад готовит отправление, а логистика отвечает за доставку.

В диаграмме применяются XOR Gateway, чтобы показать выбор только одной ветки. Первый шлюз проверяет, прошла ли оплата. Если оплата не прошла, клиент получает уведомление об ошибке, и процесс завершается. Второй шлюз проверяет наличие товара. Если товара нет, система предлагает замену или возврат, после чего заказ отменяется.

В модели выделены два Collapsed Sub-Process. Подпроцесс **«Подготовить отправление»** вынесен отдельно, потому что внутри него есть несколько складских действий: найти товар, проверить позицию, упаковать заказ и передать его в доставку. Подпроцесс **«Разобрать проблему доставки»** нужен для ситуации, когда заказ не был получен клиентом и требуется отдельная проверка со стороны поддержки или логистики.

Файл `process_main.drawio` содержит основную диаграмму. Файл `process_sub1.drawio` раскрывает подготовку отправления, а файл `process_sub2.drawio` раскрывает разбор проблемы доставки. Файл `process.bpmn` сохранён как исходный файл процесса.
